# 로한북 증빙함 업로드

로한이 준 자료를 **담당사가 한 번 거쳐 재편집한 원장**으로 만든다. 그 원장을 로한북 📂 증빙함에 올린다.
증빙함은 여러 방의 담당사가 **같은 자료를 보고** 검증하라고 만든 곳이다.
2026-11-05 에 생활사는 삼성 청구서를 봤지만 제작사는 그 청구서를 볼 수 없었다. 그래서 차액 96,143원을 아무도 설명하지 못했다. 같은 일이 다시 생기지 않게 하는 것이 목적이다.

## 대원칙
1. **원본 파일을 올리지 않는다.** 표(cols/rows), 다시 그린 그림(figure, SVG), 요약(summary)으로 바꿔서 올린다.
2. **민감정보는 가린다.**
   - 카드번호는 뒤 4자리만 남긴다.
   - 계좌번호는 뒤 4자리만 남긴다.
   - 주민번호, 주소 상세, 타인 이름, 승인번호는 지운다.
   - 무엇을 가렸는지 `masked` 칸에 적는다.
3. **덧붙이기만 한다.** 이미 있는 행에는 UPDATE·DELETE 를 하지 않는다.
   - 고칠 것이 있으면 같은 `slug` 로 `version+1` 새 행을 INSERT 한다.
   - 데이터 보존은 P0 다. 「학습방에서 올린 데이터 지우지좀마라」.
4. **증빙은 증거이고, 가계부는 장부다.**
   - 이 스킬은 `app_state`(가계부·EMR 본데이터)를 **절대 건드리지 않는다**.
   - 장부와 다른 점은 요약에 적고, 로한에게 보고만 한다.
   - 장부를 고칠지는 로한이 정한다.
5. **원본 숫자를 바꾸지 않는다.**
   - 금액·날짜는 자료에 적힌 그대로 옮긴다.
   - 추정한 값은 행에 넣지 않는다. summary 에 「추정」이라고 밝혀 적는다.
6. **암호가 걸린 파일은 암호를 받지 않는다.** 로한에게 「풀어서 다시 올려 달라」고 한다.
7. 보고는 한국어로 한다.

## 담당사(room) 정하기
| 자료 | room |
|---|---|
| 카드·통장·영수증·세금·보험료 | 생활사 |
| 진료·처방·피검사·체성분 | 순환기 |
| 교재·시험·학습 기록 | 로버트(학습) |
| 사주 관련 | 로버트(사주) |
| 그 밖 | 로한에게 묻는다 |

## 테이블 계약 — `public.sources` (Supabase 프로젝트 `ytkbrdgbklnijbwkvino`)
| 칸 | 뜻 |
|---|---|
| slug | 같은 자료의 판을 묶는 이름. 영문 소문자와 `-` 만 쓴다. 예: `samsung-tabtabo-2026-11` |
| version | 1부터. 새 판은 그 slug 의 max+1 |
| room | 위 표의 담당사 |
| kind | `card_statement` · `bank_statement` · `lab_result` · `prescription` · `other` |
| title | 한 줄 제목. 예: 「삼성카드 11/25 결제 예정 이용내역」 |
| period_from, period_to | 자료가 덮는 기간 (date) |
| as_of | 자료 기준일 (date, 필수) |
| summary | 담당사 요약 (markdown). 핵심 숫자와 장부와 다른 점 |
| cols | 표 칸: `[{"k":"date","label":"이용일"}, …]` |
| rows | 표 행: 객체 배열. 숫자는 **숫자형**으로 넣는다(쉼표 없이) |
| figure | 다시 그린 그림. `<svg …>…</svg>` 문자열 하나. 스크립트·외부 링크·이미지 삽입은 쓰지 않는다 |
| masked | 가린 항목 메모 |
| origin | 원본이 무엇이었는지. 예: 「삼성카드 앱 이용내역 캡처 3장」 |

### kind 별 행 계약 (앱이 이 키로 자동 대사를 한다 — 키 이름을 바꾸지 말 것)
**card_statement** — 한 행 = 청구서의 한 줄

| 키 | 필수 | 뜻 |
|---|---|---|
| date | 예 | 이용일 YYYY-MM-DD |
| merchant | 예 | 가맹점 |
| amt | 예 | **이번 청구 금액**. 할부면 이번 회차 금액 |
| card | 예 | **로한북 카드명 그대로**: `삼성 탭탭오` · `삼성 ID MOVE` · `우리(K패스)` · `카카오-사업자체크카드` · `네이버페이(이체)` |
| post | | 매입일 |
| inst | | 할부 개월수 (일시불이면 생략) |
| k | | 이번 회차 |
| total | | 할부 원금 |
| bill | | 청구월 YYYY-MM |
| discount | | 카드사 할인액 |

> 앱은 카드명, 이용일 ±3일, 금액 ±1원으로 가계부 거래와 맞춰 본다. 할부는 개월수와 원금(또는 회차 금액)으로 맞춘다. **period_from / period_to 를 꼭 채운다.** 그래야 반대 방향, 곧 「가계부엔 있는데 청구서엔 없는 것」도 잡힌다.

**bank_statement** — `date, time?, desc(적요), out(출금), in(입금), bal(잔액), acct(로한북 계좌명)`

**lab_result** — `date, item(항목), value, unit, ref(참고범위), flag(H/L/공백), person(본인/어머니 …)`

**prescription** — `date, drug, dose, route(투여 경로), days, person, clinic`

**other** — 자유롭게 쓴다. 단 cols 에 칸 이름을 적는다.

## 그림 다시 그리기
- 캡처나 서류 이미지에서 **구조가 기억에 도움이 될 때만** 그린다. 예: 청구서 첫 장의 합계 박스, 검사지 레이아웃, 영수증.
- SVG 하나로 그린다. viewBox 는 600 폭 안팎으로 한다. 글꼴은 `sans-serif`, 배경은 흰색이다.
- 민감정보는 그림에서도 가린다(`****1234`).
- 표로 다 담기는 자료라면 그림은 생략한다. 그림은 보조 수단이고, 진짜 데이터는 rows 다.

## 절차
1. 자료를 읽는다. 무엇인지, 기간, 기준일, 담당사를 정리해 **로한에게 한 줄로 확인**받는다.
   - 예: 「삼성카드 11/25 결제분 이용내역 · 10/13~11/12 · 생활사로 올린다 — 맞나?」
   - 로한이 처음부터 「바로 올려」라고 했으면 확인을 생략한다.
2. 행으로 옮긴다. 옮긴 뒤 **원본 합계와 rows 합계를 대조**한다. 다르면 올리지 말고 어디가 다른지 보고한다.
3. 민감정보를 가린다. `masked` 를 적는다.
4. 같은 slug 가 있는지 확인한다.
   ```sql
   select slug, max(version) v from public.sources where slug = '<slug>' group by slug;
   ```
5. INSERT 한다. `$$` 달러 인용을 써서 따옴표 문제를 피한다.
   ```sql
   insert into public.sources (slug,version,room,kind,title,period_from,period_to,as_of,summary,cols,rows,figure,masked,origin)
   values ('<slug>', <v>, '<room>', '<kind>', $$<title>$$, '<from>', '<to>', '<as_of>',
     $$<summary markdown>$$,
     $$[{"k":"date","label":"이용일"},…]$$::jsonb,
     $$[{"date":"2026-10-13","merchant":"쿠팡","amt":15830,"card":"삼성 탭탭오"},…]$$::jsonb,
     $$<svg …>…</svg>$$, $$<가린 것>$$, $$<원본 설명>$$)
   returning id, slug, version, jsonb_array_length(rows) n;
   ```
6. 올린 행을 다시 읽어 행 수와 합계를 확인한다.
   ```sql
   select sum((r->>'amt')::numeric) from public.sources, jsonb_array_elements(rows) r where id = <id>;
   ```
7. 로한에게 보고한다.
   - 무엇을 올렸는지
   - 행 수와 합계
   - 가린 것
   - 장부와 다른 점 (있으면)
   - 「로한북 📂 증빙함에서 ↻ 를 누르면 보인다」

## 하지 말 것
- `app_state`, `app_state_snap` 에 쓰는 것. 이 스킬은 증빙함만 쓴다.
- 기존 sources 행을 UPDATE·DELETE 하는 것.
- 원본 파일 전체를 base64 등으로 통째로 넣는 것.
- 추정치를 행에 섞는 것.
- 카드명을 로한북과 다르게 쓰는 것. 예: 「삼성카드」라고만 쓰면 대사가 안 된다. 카드가 불분명하면 로한에게 묻는다.
