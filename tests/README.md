# 테스트 (로한북)

세션 컨테이너는 대화창이 끝나면 사라진다. 그래서 여기 남긴다.
다음 로버트는 이 폴더를 클라우드 작업폴더로 복사해서 쓴다.

## 돌리는 법 — `run.sh` 하나면 된다

```bash
HTML=/경로/work.html ./run.sh <영역>
```

**작업 중엔 영역만, 배포 직전엔 반드시 `all`.**

| 영역 | 무엇을 고쳤을 때 | 도는 것 | 실측 |
|---|---|---|---|
| `quick` | 살아는 있나 30초 컷 | t_reg t22 | ~29s |
| `money` | 가계부·카드·할부·계좌·부채·세무·예산 | t_reg t20 t21 t25 t22 | ~34s |
| `goal` | 목표·루틴·보상·데일리·버킷 | t_reg t24 t22 | ~30s |
| `time` | 타임로그 | t_reg t18 t19 t22 | ~30s |
| `data` | 마이그레이션·저장·스냅샷 | t22 t23 t_reg t24 t25 | ~40s |
| `css` | 레이아웃·반응형 | t14 t_reg | ~11s |
| **`all`** | **배포 직전 · 예외 없이** | 10개 전부 | **~44s** |

`./run.sh t25 t14` 처럼 파일명을 직접 나열해도 된다.
결과는 `tests/.out/<이름>.log` 에 남는다.

> **왜 이렇게 나눴나 (2026-08-21).** 매 수정마다 10개를 직렬로 돌려 **114초**가 걸렸고,
> 한 번 업데이트에 서너 번 반복하니 검증에만 8분이 갔다. 병렬 + 영역 분할로 **8분 → 40초**.
> ⚠️ **영역 태그는 '보통 이것만 깨진다'는 경험칙이지 보증이 아니다.** 그래서 배포 직전 `all` 은 협상 대상이 아니다.
> `t22`(극단상태) 는 어느 영역에나 끼워 넣었다 — 마이그레이션은 어디서든 깨진다.

## 실행 환경
- Playwright: `/opt/pw-browsers` 에 chromium 이 이미 있다. **`playwright install` 하지 말 것.**
- 각 스크립트는 supabase 를 스텁으로 갈아끼운다. 실제 서버에 붙지 않는다.
- 스텁은 `update().eq().eq().select()` 체인을 지원해야 한다 (v1.1 동기화 엔진).
- CPU 2개라 병렬 이득은 약 2.6배에서 멈춘다.

`select data->'goals' as goals, data->'rewards' as rewards from app_state;`

## 규칙
- **테스트가 계속 같은 걸 지적하면 테스트가 틀린 게 아니라 코드가 틀린 것이다.** (v1.0에서 9일 무시했다가 터짐)
- **새 기능 테스트는 '잘 된 상태'가 아니라 '빈 상태'부터 먹인다.** (v1.1에서 SEED 키 7개 누락 발견)
- **상수를 박지 마라 — 경로도 날짜도.**
  0820: `/home/claude/work.html` 을 박아둬 새 세션에서 5개가 통째로 안 돌았다.
  0821: `t23` 이 `'2026-08-20'` 을 박아둬 하루 지나자 2건 빨간불 — **코드는 멀쩡했다.**
  → HTML 은 `process.argv[2]`, 시드는 `path.join(__dirname,…)`, 날짜는 실행 시점 계산(`TODAY`/`DAYS(n)` — `t23.js` 상단).
  브라우저로 넘길 땐 **인자로 전달**해야 한다. Node 변수는 페이지 안에 없다.
- **빨간불이면 코드부터 의심하되, 상수부터 확인한다.** 둘 다 안 하면 시간을 버린다.
- `t16.js` 는 폐기 — v11에서 `#v-timelog` 탭이 데일리에 합쳐져 사라졌다.
